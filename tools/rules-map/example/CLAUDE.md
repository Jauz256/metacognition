# Rules

This is a small example rules file. The builder reads one rule per top-level bullet.

- Clarify the request before any change that touches more than three files.
- Restate the goal in one line and wait for a yes before a big build.
- Keep dependencies minimal; do not add a package when the standard library will do.
- Never leave console.log or debug statements in shipped code.
- Run lint and typecheck before every commit.
- Never say "done" without pasting the command that proves it.
- Answer first, details second: the first line of a reply is the answer.
- Commit atomically, with a message that names the change.
- When the same correction comes twice, write it down as a rule, not a comment.
- Be direct. No filler words.
